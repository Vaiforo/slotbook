# SlotBook

Сервис записи на консультации: публичная страница специалиста, календарь
и доступное время из настоящего PostgreSQL. Все даты показываются в часовом
поясе специалиста. Выбранное время видно рядом с расписанием.

В интерфейсе доступны выбор времени, запись по имени и email, подтверждение
с секретной ссылкой и отмена встречи до её начала. В кабинете специалиста доступны вход, список записей и управление расписанием.

## Стек

- Python 3.14, FastAPI, Pydantic, SQLAlchemy 2, psycopg 3, Alembic.
- PostgreSQL 18, Docker Compose.
- React 19, TypeScript strict, Vite, React Router, TanStack Query.
- Tailwind CSS 4, компоненты по схеме shadcn/ui на Radix, Lucide.
- React Hook Form и Zod для доступной валидации формы записи.
- Temporal для корректных границ календарного дня в IANA timezone.
- uv/uv.lock и npm/package-lock.json для воспроизводимой установки.

## Запуск

Требуются Node.js 24 LTS, npm, [uv](https://docs.astral.sh/uv/getting-started/installation/),
GNU Make и Docker Compose. uv установит Python 3.14 при необходимости.
Все команды ниже выполняются из корня проекта.

```bash
make install
# Необязательно: локальные значения уже заданы по умолчанию.
cp .env.example .env
make db-up
make migrate
make seed
```

Затем в двух отдельных терминалах:

```bash
make backend
```

```bash
make frontend
```

Откройте [страницу специалиста](http://127.0.0.1:5173/s/demo).
Seed создаёт свободное время на завтра, поэтому нажмите «Завтра».
Корневой URL перенаправляет на `/s/demo`; `/s/:slug` открывает специалиста по slug.
Профиль и расписание загружаются с API, без демонстрационных подстановок в UI.

Календарь позволяет выбрать день, перейти к другому месяцу или ввести дату
в диалоге. Прошедшие дни недоступны. Дата запроса и часы слотов вычисляются
по timezone специалиста, независимо от timezone браузера. При смене даты
выбор времени сбрасывается. Есть состояния загрузки, пустого расписания,
неизвестного специалиста и сетевой ошибки с повторной попыткой.

После выбора времени заполните имя и email и нажмите «Подтвердить запись».
Во время отправки форма и выбор времени заблокированы. Если слот уже занят,
расписание обновится и предложит выбрать другой. Ошибки данных сохраняют ввод;
при сетевой ошибке интерфейс предупреждает, что запись могла сохраниться.
POST-запросы автоматически не повторяются.

Экран подтверждения позволяет скопировать секретную ссылку вида
`/manage/<id>#token=…`; если буфер обмена недоступен, ссылку можно выделить вручную.
Письмо с подтверждением пока не отправляется. Сохраните ссылку самостоятельно:
она даёт доступ к имени, email и отмене встречи.

Страница `/manage/:id` извлекает секрет из fragment до запуска React/router и
сразу очищает адрес. Повторное открытие ссылки в той же вкладке также поддерживается.
Токен остаётся только в памяти, передаётся API через `Authorization: Bearer` и
не попадает в query keys, localStorage, sessionStorage или history state.
После перезагрузки страницы снова откройте сохранённую полную ссылку.
Чтение записи ничего не отменяет: отмена требует отдельного подтверждения.
На странице управления дата показана в явно подписанном часовом поясе браузера;
в расписании и первоначальном подтверждении — в часовом поясе специалиста.

```text
React → /api/v1 через Vite proxy → FastAPI → PostgreSQL → JSON → React Query
```

Vite проксирует `/api` и `/health` в FastAPI. Dev-серверы слушают loopback;
нужны свободные порты 5173 и 8000. Остановка — Ctrl+C.
`make db-stop` останавливает PostgreSQL, сохраняя данные в Docker volume.

## Настройки

Backend и Vite читают корневой `.env`; переменные процесса имеют приоритет.
После изменения настроек перезапустите серверы.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SLOTBOOK_APP_NAME` | `SlotBook` | Имя API |
| `SLOTBOOK_ENVIRONMENT` | `development` | development / test / production |
| `SLOTBOOK_LOG_LEVEL` | `INFO` | Уровень JSON-логов |
| `SLOTBOOK_DATABASE_URL` | Локальный URL из `.env.example` | SQLAlchemy URL с `postgresql+psycopg` |
| `POSTGRES_PASSWORD` | `slotbook_local_only` | Пароль локальной БД |
| `POSTGRES_PORT` | `5432` | Порт PostgreSQL на 127.0.0.1 |
| `SLOTBOOK_PUBLIC_ORIGIN` | `http://127.0.0.1:5173` | Точный browser origin без завершающего слеша; production требует HTTPS |
| `API_PROXY_TARGET` | `http://127.0.0.1:8000` | Серверный адрес dev proxy |

Пароль по умолчанию предназначен только для локальной разработки. При смене
пароля или порта измените также `SLOTBOOK_DATABASE_URL`. Изменение env не меняет
пароль уже инициализированного PostgreSQL volume. Переменные `VITE_*` публичны;
секреты в них хранить нельзя. Для приложения они не требуются.

Makefile размещает кэши uv/npm и управляемый Python в игнорируемой `.cache/`.
Backend environment находится в `backend/.venv/`. `.env`, окружения, кэши и
результаты сборки исключены из Git.

## База данных

Compose запускает PostgreSQL 18 с healthcheck. Порт опубликован только на
127.0.0.1, volume `postgres_data` смонтирован в `/var/lib/postgresql`.
`make migrate` применяет Alembic к текущей БД, `make seed` явно добавляет
синтетические демонстрационные данные.

Таблицы: users, sessions, specialists, slots, bookings. Ограничения БД запрещают
пересекающиеся слоты одного специалиста (включая закрытые), интервалы не по
30 минут и две confirmed-записи на один слот. Соседние интервалы допустимы.
Отменённые записи сохраняются. Моменты времени хранятся как timestamptz,
IANA timezone — отдельной строкой.

Seed транзакционный и повторяемый: `demo@example.invalid`, специалист `demo`,
`Asia/Omsk`, четыре слота на завтра 10:00–12:00 по Омску относительно часов БД.
Повтор в тот же день не дублирует данные; в другой день добавляется новая
будущая дата. Seed не открывает закрытые слоты и не стирает историю.
По умолчанию вход демо-владельца отключён. Чтобы включить его, задайте
`SLOTBOOK_DEMO_PASSWORD` (не менее 12 символов) в окружении команды `make seed`.
Пароль сохраняется только как Argon2id-хеш. Повтор seed без пароля сохраняет
текущий хеш, явное задание пароля обновляет его и отзывает сессии демо-владельца.
Не помещайте пароль в исходный код или `VITE_*`.

SQLAlchemy-модели — `backend/app/models.py`. Каждый запрос получает отдельную
AsyncSession; commit принадлежит сценарию. Engine создаётся при старте
приложения и закрывается при остановке. Импорт приложения не открывает БД.

## API

- [Swagger UI](http://127.0.0.1:8000/docs).
- `GET /health/live` — жизнь процесса, без проверки готовности БД.
- `GET /api/v1/specialists/{slug}` — публичный профиль без приватных полей.
- `GET /api/v1/specialists/{slug}/slots?from=…&to=…` — будущие свободные open-слоты.
- `POST /api/v1/bookings` — создать запись; manage token выдаётся один раз после commit.
- `GET /api/v1/bookings/{booking_id}` — прочитать свою запись по Bearer token.
- `POST /api/v1/bookings/{booking_id}/cancel` — отменить её до начала встречи.

`from`/`to` обязательны, ISO 8601 с offset или `Z`. Диапазон `[from, to)` по
началу слота — не больше 31 дня. `limit` — 1–100, `offset` — 0–10000.
При использовании curl применяйте `--get --data-urlencode`, чтобы сохранить
`+` в часовом поясе. Неизвестный специалист — 404, неверные параметры — 422.

Все ответы содержат `X-Request-ID`. Ошибка имеет вид
`{error: {code, message, request_id}}`. JSON-логи содержат шаблон маршрута,
статус и длительность, без query strings, контактов и токенов.
[Подробный HTTP-контракт](docs/api-contract.md).

Pydantic/OpenAPI — источник TypeScript-типов:

```bash
make api-generate
make api-check
```

Обе команды работают без БД. Проверка обнаруживает расхождение OpenAPI и
сгенерированных типов без перезаписи файлов. HTTP-клиент поддерживает
AbortSignal, same-origin credentials и типизированные ошибки. React Query
повторяет запрос сети/5xx не более одного раза; 4xx не повторяются.
Автоматические повторы mutations отключены.

## Проверки

```bash
make check
make db-test
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium make smoke
```

`make check` выполняет api-check, Ruff/format, mypy, backend unit/smoke tests,
ESLint, Vitest, TypeScript strict и frontend build. Без `SLOTBOOK_TEST_ADMIN_URL`
интеграционные backend-тесты пропускаются; их отдельно запускает `make db-test`.

Для браузерных проверок сначала выполните `make db-up` и остановите dev-серверы.
`make smoke` сам создаёт случайную БД `slotbook_browser_<uuid>`, применяет миграции,
запускает seed, FastAPI и Vite. После штатной остановки тестовая БД удаляется.
Рабочие данные не изменяются. Проверяются реальные профиль/слоты, выбор времени,
смена даты, клавиатура и диалог, loading/empty/error/retry, неизвестные страницы
и размеры 390/768/1440 px. Также проверяются запись → отмена → повторная запись,
конфликт с другим клиентом, сохранённая ссылка, очистка fragment, отсутствие
секрета в хранилищах/URL запросов/консоли и восстановление после перезагрузки.
Vitest проверяет форму, 409/422/сетевые ошибки и блокировку повторной отправки.
Сетевые ошибки и задержки вводятся только в тестах;
успешные ответы приходят из настоящего API. Скриншоты — в `frontend/test-results/`.

Если системного Chromium нет, установите браузер Playwright:

```bash
cd frontend
npx playwright install chromium
cd ..
make smoke
```

`make db-test` также создаёт собственную БД `slotbook_test_<uuid>`, проверяет
upgrade → downgrade → upgrade, ограничения, seed, read API и удаляет её.
Адрес сервера можно переопределить через `SLOTBOOK_TEST_ADMIN_URL`;
нужны PostgreSQL 18 и право CREATEDB. Пользовательская БД не откатывается.

## Сборка и ограничения

`frontend/dist/` содержит статическую сборку. Для production требуется reverse
proxy с маршрутизацией `/api`, `/health`, `/docs`, `/openapi.json` в FastAPI
и SPA fallback для `/s/:slug`, `/manage/:id`, `/login` и `/dashboard/*`. Production proxy, контейнеры приложения, CI,
HTTPS и публичный деплой пока не настроены.

Просмотр доступности не гарантирует последующее бронирование: API создания
повторно проверяет слот в транзакции после блокировки строки. Время берётся из
PostgreSQL после ожидания блокировки. Повторная отмена старой записи не затрагивает
новую запись на том же слоте. Исходный manage token хранится только у клиента;
сервер хранит SHA-256-хеш. При потере ответа после commit повтор POST не
гарантирует восстановление результата и может вернуть 409. Интерфейс явно
сообщает о неопределённом результате при потере ответа; восстановление
утраченного токена пока не поддерживается.


Тесты бронирования в `make db-test` включают 20 одновременных TCP HTTP-запросов
с барьером старта и 20 независимыми соединениями PostgreSQL: один 201,
остальные 409, в БД одна confirmed-запись. Также проверяются чтение/отмена по
токену, ожидание блокировки до начала встречи, идемпотентная отмена, rollback
после flush и отсутствие обхода авторизации через cookie/query. Проверки
используют только одноразовые тестовые БД, не рабочие данные.

## Доступ владельца через API

`POST /api/v1/auth/login` принимает email/password и требует заголовок Origin,
равный `SLOTBOOK_PUBLIC_ORIGIN`. Возвращает HttpOnly/SameSite=Lax cookie `session`
на 12 часов. Secure включён для HTTPS; обычный HTTP допускается только для
loopback в development/test. Production-конфигурация с HTTP отклоняется.

`GET /api/v1/auth/me` возвращает id/email/CSRF token и собственный профиль специалиста. Для `POST /auth/logout`,
`POST /slots` и `PATCH /slots/{id}` нужны cookie, Origin и X-CSRF-Token.
`GET /api/v1/me/bookings` поддерживает from/to/status/limit/offset и возвращает
только записи текущего владельца. Чужие слоты нельзя изменять (404).

Закрытие занятого слота возвращает 409, не отменяя запись клиента. Закрытие и
бронирование сериализуются блокировкой строки слота. Создание/обновление слотов
проверяет время PostgreSQL; пересечения дополнительно запрещены ограничением БД.
Аутентификация и изменения используют одну транзакцию; ответ отправляется после
commit. Нет регистрации, восстановления пароля и rate limiting.

## Кабинет специалиста

Откройте `/login` или ссылку «Кабинет специалиста» в шапке. Демо-владелец
`demo@example.invalid` входит с паролем, который вы явно задали при `make seed`.
В production секретная cookie требует HTTPS; локальный Origin должен совпадать
с `SLOTBOOK_PUBLIC_ORIGIN`, включая порт.

`/dashboard` показывает записи с фильтрами дат (до 31 дня) и статуса, по 20
записей на страницу. Фильтры сохраняются в URL. `/dashboard/schedule` показывает
неделю и слоты выбранного дня: свободные, закрытые и занятые. Можно опубликовать
30-минутный слот, закрыть его с подтверждением или открыть снова. Занятые и
прошедшие слоты недоступны для изменения; окончательное решение принимает API.
Дата и время в кабинете всегда указаны в часовом поясе специалиста.
Неоднозначное/несуществующее время при переводе часов отклоняется с объяснением.

`GET /api/v1/me/slots` возвращает собственные слоты, включая закрытые и прошедшие,
с признаком `has_booking`, без контактов клиентов. Профиль берётся из текущей
сессии, без пользовательского ввода specialist_id. При отсутствии профиля
показывается сообщение о необходимости его настройки.

При 401 приватные запросы отменяются, кэш очищается, интерфейс возвращает на
вход с сохранением выбранной страницы и фильтров. Выход отзывает сессию на сервере
и очищает приватный кэш. Ключи запросов содержат ID владельца; при смене аккаунта
данные прежнего владельца не отображаются. Пароль и CSRF не сохраняются в браузерных
хранилищах. Клиентская проверка сессии дополняет серверную проверку доступа.

Браузерные тесты используют двух синтетических владельцев только в одноразовой
тестовой БД. Проверяются публикация → клиентская запись → список владельца,
закрытие/открытие слота, конфликт времени, фильтры, выход/смена владельца,
401 после чтения/изменения, сетевые ошибки и размеры 390/768/1440 px.
