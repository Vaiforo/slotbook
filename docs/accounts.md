# Аккаунты и роли

Первый этап добавляет регистрацию клиента и специалиста, общую cookie-сессию,
личные данные и смену пароля. Каталог, профессиональный редактор и клиентские
бронирования относятся к следующим этапам.

## Подготовка

После установки зависимостей выполните `make migrate` перед запуском API.
Миграция `c1420a01` назначает существующим владельцам профессиональных профилей
роль `specialist`, остальным — `client`. Имя и часовой пояс специалиста
переносятся в аккаунт. Существующие записи и сессии сохраняются.
Профессиональные профили получают статус `draft` и новые поля для второго этапа.

## Пользовательские сценарии

- `/register`: выбор роли, затем имя, email, пароль и его подтверждение.
  Специалист дополнительно выбирает категорию.
- `/login`: общий вход для обеих ролей.
- `/dashboard`: кабинет с навигацией по роли.
- `/dashboard/profile`: имя, необязательный телефон и часовой пояс IANA.
  Email отображается без возможности изменения.
- `/dashboard/security`: смена пароля с проверкой текущего. Все сессии
  завершаются; требуется повторный вход.

Пароль содержит от 12 до 1024 символов; пробелы сохраняются.
Email нормализуется; уникальность гарантируется PostgreSQL. Роль нельзя менять
через профиль. Специалист автоматически получает уникальный slug и черновик.
Подтверждение email и восстановление пароля пока не реализованы.

## API

- `POST /api/v1/auth/register` — 201 и Identity, cookie после commit.
- `POST /api/v1/auth/login` — 204 и cookie.
- `GET /api/v1/auth/me` — Identity с ролью и CSRF.
- `POST /api/v1/auth/logout` — 204.
- `GET /api/v1/me/profile` — Identity.
- `PATCH /api/v1/me/profile` — полная форма личных данных, Identity.
- `POST /api/v1/auth/change-password` — 204, завершение всех сессий.

Изменения профиля требуют Origin и X-CSRF-Token; регистрация и вход — Origin.
Сессии хранятся в БД в виде хешей. Отключённый аккаунт не может войти или
использовать существующую сессию. Специализированные операции проверяют роль.

`SLOTBOOK_REGISTER_LIMIT` задаёт лимит регистраций на IP за общее окно
`SLOTBOOK_RATE_WINDOW_SECONDS` (по умолчанию 5). При наличии Redis лимит
разделяется всеми процессами; при его недоступности регистрация возвращает 503.

## Проверки

`make check` проверяет API-контракт, типы, форматирование, тесты и сборку.
Интеграционные тесты требуют `SLOTBOOK_TEST_ADMIN_URL` и создают собственные
случайные базы PostgreSQL 18. `frontend/tests/accounts.spec.ts` проверяет обе
роли в браузере: регистрация, сохранение профиля, смена пароля и повторный вход.
