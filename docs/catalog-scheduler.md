# Автопродление расписания тестовых специалистов

Десять синтетических профилей создаются командой `make seed-specialists`.
При первом наполнении расписание строится со завтра на 14 календарных дней.
Графики специалистов и 30-минутные интервалы остаются прежними.

Первая дата продления — первая среда после завершения первых семи дней начального
периода. Затем продление выполняется каждую среду в часовом поясе `Asia/Omsk`.
Каждый запуск добавляет семь дней после сохранённой границы расписания.

Например, наполнение 9 ноября 2026:

| Событие | Период новых слотов | Расписание создано по |
|---|---|---|
| Начальное наполнение | 10–23 ноября | 23 ноября |
| Среда, 18 ноября | 24–30 ноября | 30 ноября |
| Среда, 25 ноября | 1–7 декабря | 7 декабря |

Процесс проверяет срок раз в минуту. После простоя он обрабатывает пропущенные
среды, но не создаёт интервалы в прошлом или на текущую дату. Состояние хранится
в таблице `catalog_schedules`: начало исходного периода, созданная граница и
следующая среда. Слоты и новая граница фиксируются одной транзакцией. Блокировка
PostgreSQL предотвращает двойное продление несколькими процессами.

Закрытые и занятые слоты не меняются; пересекающиеся интервалы пропускаются.
Профили не перезаписываются и не публикуются автоматически. Если часовой пояс
синтетического профиля изменён с Asia/Omsk, его расписание не продлевается по
старому шаблону. Обычные зарегистрированные специалисты не затрагиваются.

## Сервер

После обновления образа и применения миграции `f1420a04` сервис
`catalog-scheduler` автоматически запускается вместе с production Compose.
Его нужно оставить работающим наряду с API. Уже существующие синтетические
профили подхватываются без повторного создания аккаунтов.

```sh
docker compose -f compose.production.yaml logs -f catalog-scheduler
```

Повторный `make seed-specialists` не сбрасывает границу на «сегодня + 14»:
он дополняет текущий период и обрабатывает наступившее продление.

## Локальная разработка

Примените миграции и наполните каталог, затем запустите отдельный терминал:

```sh
make catalog-scheduler
```

Без Make, из `backend/`:

```sh
uv run --frozen python -m app.catalog.scheduler
```

Однократная проверка наступившего срока:

```sh
uv run --frozen python -m app.catalog.scheduler --once
```

Команда не создаёт каталог автоматически, если начальное наполнение не выполнено.
