# Каталог и запись

Подготовьте локальную среду по README, затем выполните:

```sh
make db-up
make migrate
make seed-specialists
```

В разных терминалах запустите `make backend` и `make frontend`.
Откройте http://127.0.0.1:5173/.

В каталоге десять вымышленных специалистов: три медицинских, три сантехника,
два юриста и два специалиста доставки. Профили заполнены описаниями и услугами,
свободное расписание создано на следующие 14 дней в Asia/Omsk. Броней нет.
Вход в эти аккаунты отключён, общих паролей нет. Команду можно запускать повторно:
дубликаты не создаются, правки профилей и закрытые интервалы сохраняются.

## Клиент

1. Найдите специалиста, откройте профиль и выберите свободное время.
2. Перейдите к регистрации, выберите «Клиент», заполните имя, email и пароль.
3. После регистрации откроется выбранная дата и интервал. Доступность проверяется
   заново; автоматической записи нет. Нажмите «Подтвердить запись».
4. Откройте личный кабинет. В обзоре отображается ближайшая запись, в разделе
   «Мои записи» — предстоящие, прошедшие и отменённые записи с фильтрами дат.
5. Для отмены до начала встречи нажмите «Отменить запись» и подтвердите действие.

Контакты брони берутся из аккаунта и сохраняются снимком. Изменение личных данных
не переписывает прошлые брони. Чужие записи недоступны даже по известному ID.
Прошедшая запись означает только истечение времени, а не подтверждение оказания услуги.

## Специалист

Зарегистрируйте собственный аккаунт с ролью «Специалист» и категорией. Заполните
«Публичный профиль», добавьте услуги и опубликуйте страницу. Создайте смены через
предпросмотр. В обзоре отображаются статус профиля, записи на сегодня и ближайшие клиенты, а в разделе
«Записи» — список клиентов и фильтры. В расписании можно закрывать свободное время.

## Обновление существующей базы

Перед миграцией `e1420a03` остановите dispatcher и worker уведомлений. Миграция
удаляет известные синтетические ID старого демо вместе с их слотами, бронями,
событиями и сессиями. Остальные аккаунты и брони сохраняются. Откат схемы не
восстанавливает удалённые синтетические данные. Страница `/s/demo` ведёт в каталог.
Исторические гостевые брони не присоединяются к аккаунтам по email; старые секретные
ссылки продолжают работать. Новые записи требуют сессии клиента, Origin и CSRF.

## Проверка API

`python scripts/booking-journey.py --book-and-cancel` проверяет регистрацию,
бронирование и отмену в локальной среде с наполненным каталогом.
Для другого origin задайте `SLOTBOOK_PUBLIC_ORIGIN`, для адреса API — `--base-url`.
Скрипт создаёт отдельного синтетического клиента и никогда не выводит его пароль
или секретную ссылку. Полная схема API находится в `docs/openapi.json`.
