# Подбор времени по описанию

Кнопка «Подобрать по описанию» открывает диалог на странице специалиста.
Например: «Завтра с 15:00 до 18:00». Пользователь видит распознанную дату,
диапазон начала встречи, часовой пояс и свободные варианты из PostgreSQL.
Выбор варианта открывает обычную форму имени/email. Запись появляется только
после «Подтвердить запись» и повторной проверки доступности в транзакции.

Без подключённой модели поиск возвращает понятный отказ и предлагает календарь.
В рабочем приложении нет имитации LLM или выдуманных слотов.

## Обработка запроса

`POST /api/v1/specialists/{slug}/search` принимает только `{"text":"…"}`:
1–500 символов после trim. Неизвестный специалист — 404, неверное тело — 422.
Ответ 200 содержит `status`, `message`, `timezone`, `from`, `to`, `items`.

| status | Результат |
|---|---|
| `found` | До 48 реальных будущих open-слотов без confirmed-записи |
| `empty` | Распознанный диапазон пуст; можно изменить запрос |
| `clarification` | Нужен один день или однозначное время; повторите полное пожелание |
| `unavailable` | Модель отключена, исчерпан бюджет, таймаут или некорректный ответ; доступен календарь |

Сервер получает специалиста по slug, передаёт модели только текст, текущее местное
время и timezone. Контакты, история записей, ID слотов и секретные ссылки не передаются.
Пользовательский текст сам может содержать личные данные: интерфейс просит их не
указывать. Запросы и ответы модели не сохраняются в БД или логах приложения.
`store: false` передаётся провайдеру; его политика обработки данных всё равно действует.

[LLMClient](../backend/app/ai/client.py) изолирует HTTP-провайдера. Chat Completions
с `response_format: json_schema`, `strict: true` возвращает `date`, `time_from`,
`time_to`, `needs_clarification`, `reason`. Дополнительные поля запрещены;
tool calls, refusals, обрезанный ответ и неверный JSON отклоняются. Инструменты
модели вообще не предоставляются. Доступности у модели нет.

[Pydantic и проверка диапазона](../backend/app/ai/service.py) допускают один день
от сегодня до 30 дней вперёд в timezone специалиста. Поиск по началу слота:
`[from, to)`. Без времени — весь день. Точное время задаётся минутным диапазоном.
Утро — 09:00–12:00, день — 12:00–18:00, вечер — 18:00–23:59.
«После трёх», несколько дней и ночной диапазон требуют уточнения. Несуществующие
и неоднозначные локальные границы при переходе DST также требуют уточнения.
Интерпретация естественного языка может ошибаться: распознанный диапазон показывается
до выбора, а окончательное создание записи проходит обычный endpoint.

## Подключение провайдера

Адаптер рассчитан на OpenAI Chat Completions или совместимый HTTPS endpoint,
поддерживающий strict JSON Schema, `max_completion_tokens` и `store`.
В `.env` или защищённом production env задайте:

```dotenv
SLOTBOOK_REDIS_URL=redis://127.0.0.1:6379/0
SLOTBOOK_AI_MODEL=gpt-4.1-mini
SLOTBOOK_AI_API_KEY=<секретный ключ>
SLOTBOOK_AI_URL=https://api.openai.com/v1/chat/completions
SLOTBOOK_AI_TIMEOUT_SECONDS=8
SLOTBOOK_AI_DAILY_REQUEST_LIMIT=100
SLOTBOOK_AI_LIMIT=5
```

В Compose используйте внутренний Redis URL из `deploy/.env.example`.
Пример модели — начальная конфигурация, не результат сравнения качества моделей.
Частичная конфигурация или HTTP URL запрещены. При пустых model/key AI отключён.
После `make migrate` перезапустите API. Ключи остаются на backend, вне Git и `VITE_*`.
Для внешнего провайдера нужен сетевой доступ к его HTTPS-хосту.

Общий таймаут — 8 секунд (настраивается от 1 до 15), соединение — до 3 секунд,
HTTP-ответ — не более 64 KiB, content — до 4096 символов, completion — до 500 токенов.
Автоматических повторов и перенаправлений HTTP нет, в том числе на 429/5xx.

## Лимиты расходов

Redis ограничивает поиск до 5 запросов/IP за общее окно (60 секунд по умолчанию)
независимо от slug. 429 содержит Retry-After; сбой Redis даёт 503 до вызова модели.
Включённая модель требует Redis и в development.

Таблица `ai_usage` хранит только UTC-день и число зарезервированных вызовов.
Атомарный PostgreSQL upsert не пропускает больше `AI_DAILY_REQUEST_LIMIT` вызовов
в сутки между процессами. Reservation фиксируется **до** HTTP: таймаут, отказ,
неверный ответ и сбой процесса тоже расходуют попытку, возврата бюджета нет.
Перезапуск Redis/API не сбрасывает этот счётчик. Все процессы должны иметь одинаковый
лимит. Новая миграция `b8f218ca7d10` добавляет таблицу без изменения прежних миграций.
Восстановление старой копии БД восстанавливает и старый счётчик — учитывайте это
перед включением AI после восстановления.

Ограничены число вызовов, размер ввода и completion. Это не денежный биллинг:
стоимость зависит от модели и тарифа. Установите дополнительный денежный бюджет
в проекте провайдера; его расход учитывает и другие приложения с тем же ключом.

## Проверка качества

`make ai-eval` запускает 25 **contract-fixtures** без сети и ключей, входит в
`make check`/CI. Это проверка нормализации и защитных реакций на заранее заданные
ответы, не accuracy модели. Набор включает относительные даты, границы года/UTC,
DST, неоднозначности, попытку вызвать инструмент, лишний slot ID, невалидный JSON
и отказ. Пустой день и актуальность слотов отдельно проверяются с настоящей БД.

После настройки провайдера и миграций:

```bash
cd backend
uv run --frozen python -m scripts.eval_ai --live
```

Eval-набор включён и в API Docker-образ; внутри него команда —
`python -m scripts.eval_ai --live`.

Live-режим делает до 20 платных вызовов по синтетическим пожеланиям через тот же
адаптер и суточный бюджет; 5 случаев повреждённого ответа остаются fixtures.
JSON-отчёт различает `source: provider/fixture` и содержит expected/actual.
Он не печатает ключи и сырой ответ модели. Итоги можно сохранить локально.

В версии 0.4.0 локальный набор проходит 25/25. Живой провайдер не подключён,
live-eval и качество распознавания реальной моделью не проверены. Браузерные тесты
используют отдельный тестовый LLM-адаптер и настоящие API/PostgreSQL; Docker-проверка
использует рабочий API с отключённым AI. RAG и граф диалога не используются.
