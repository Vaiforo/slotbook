# Демо за 2–3 минуты

Демо предназначено для локальной БД с синтетическими данными. Подготовку выполните
до показа. Команды — из корня репозитория; нужны Node 24 LTS, uv и Docker Compose.

```bash
make install db-up migrate
read -r -s -p 'Пароль демо-владельца (12+ символов): ' SLOTBOOK_DEMO_PASSWORD
printf '\n'
export SLOTBOOK_DEMO_PASSWORD
make seed
unset SLOTBOOK_DEMO_PASSWORD
```

В двух терминалах запустите `make backend` и `make frontend`. Откройте
<http://127.0.0.1:5173/s/demo> и отдельно <http://127.0.0.1:5173/login>.
Вход: `demo@example.invalid` и введённый пароль. Seed создаёт на завтра четыре
слота 10:00–12:00 в `Asia/Omsk`. Повторный seed не удаляет историю и не открывает
закрытые слоты; при необходимости опубликуйте дополнительное время в кабинете.
Повтор seed с паролем отзывает прежние сессии демо-владельца.

| Время | Действие | Что видно |
|---|---|---|
| 0:00–0:40 | На публичной странице нажмите «Завтра», выберите время и введите «Демо-клиент», `demo-client@example.com`. Подтвердите запись. | Подтверждение и секретная ссылка; время исчезает из свободных. |
| 0:40–1:15 | Скопируйте ссылку. В кабинете откройте записи, включите завтрашнюю дату и обновите список. | Новая подтверждённая запись и контакты клиента. |
| 1:15–1:50 | Откройте полную ссылку в отдельной вкладке, подтвердите отмену. | Статус «Отменена». После обновления публичного расписания время снова свободно. |
| 1:50–2:30 | В кабинете выберите завтрашнюю дату в расписании, закройте свободный слот и затем откройте его. | Изменение доступности на публичной странице. Занятый слот закрыть нельзя. |

Ссылку клиента нельзя показывать в публичной записи экрана: это credential,
дающий доступ к контактам и отмене. После открытия fragment очищается; для повторного
открытия после перезагрузки нужна исходная полная ссылка. Письма не отправляются.

## Тот же публичный сценарий через API

При работающем backend и локальном seed:

```bash
python3 scripts/demo-api.py --book-and-cancel
# Через запущенный локальный production Nginx:
python3 scripts/demo-api.py --base-url http://127.0.0.1:8080 --book-and-cancel
```

Скрипт выбирает свободный слот `demo` в ближайшие семь дней, создаёт синтетическую
запись, читает её с Bearer token, отменяет и проверяет, что слот снова свободен.
Он не печатает токен и не сохраняет его в файлы. Отменённая запись остаётся в БД.
Работает только с loopback URL; не направляйте его через туннель на рабочую БД.
При сетевой ошибке запись могла сохраниться: скрипт не повторяет POST автоматически.

В production seed запускается явно: `docker compose --env-file .env.production
-f compose.production.yaml exec api python -m scripts.seed_demo` (в одну строку).
Для живых данных демо-профиль создавать не требуется. Сценарий входа в production
требует HTTPS; локальный порт 8080 обслуживает только внутренний HTTP.
